# TjLightRAG

JDK 21 / Spring Boot 4.1.2 / Spring AI 2.0.2 / PostgreSQL 18 + pgvector 0.8.7 / React + TypeScript + Vite + Tailwind CSS。
版本来自 Maven Central 最新稳定版（2026-10-26），不采用 RC/M 预发布版本。
文本、流式回答和向量调用使用 Spring AI 官方 `OpenAiChatModel` / `OpenAiEmbeddingModel`，可配置模型、抽取实体关系并构建/切换图谱与向量索引。五种模式检索、回答、POST SSE 流式输出和可选重排已接入（真实供应商质量仍待联调）；文档解析与分块不需要模型密钥。

## 目录

- backend：Maven 父项目，common（通用代码）、document-parser（独立文档解析）、app（业务与智能体调用契约）、agent（ReAct、工具、上下文及调用跟踪）、bootstart（启动与配置）。app 依赖 common 和 document-parser，agent 依赖 app，bootstart 依赖 app 和 agent；app 不依赖 agent 实现。智能体单元测试在 agent，跨模块集成测试在 bootstart。
- frontend：pnpm 前端，中英文登录、知识库、文档/任务、模型配置及索引管理
- docs：代码规范
- docker：前后端同一应用镜像，数据库独立容器，Compose 部署

## 本地开发

需要 Java 21、Maven 3.9+、Node 24、pnpm 11.25.0、Docker Compose。

```sh
docker compose -f docker/compose.dev.yml up -d --wait
cd backend
mvn clean install
mvn -pl bootstart spring-boot:run
```

另开终端：

```sh
cd frontend
pnpm install --frozen-lockfile
pnpm dev
```

前端 Vite 将 /api 代理至服务端 8080。默认 dev profile 连接 localhost:5432/tjlightrag；数据库账户为 tjlightrag / tjlightrag，Flyway 复用应用 datasource。
只需通过 DB_URL、DB_USERNAME、DB_PASSWORD 配置数据库连接，账号需具备业务读写和数据库迁移权限。JPA 只验证结构，Flyway 执行增量迁移。开发向量空间为明确的 fixture-3d / 3 维；生产必须显式配置历史固定空间标识与维度（新部署可用 legacy-bootstrap / 3）。本阶段实际模型在管理员配置页选择，与历史空间区分，切换实际模型不修改历史空间参数。已有 Compose 数据卷不会自动修改数据库账号密码；DB_PASSWORD 应使用原迁移账号 tjlightrag 的密码（或先在数据库中修改该账号密码）。

默认登录：admin / 123456。密码使用 BCrypt 存储；生产部署前应更换默认管理员密码。
认证使用 HttpOnly、SameSite=Lax 会话 Cookie；写请求先 GET /api/auth/csrf，使用 X-CSRF-TOKEN 请求头。
登录 POST /api/auth/login（表单），用户 GET /api/auth/me，注销 POST /api/auth/logout。

## 单镜像部署

```sh
cp docker/.env.example docker/.env
# 编辑 docker/.env，填写两套数据库密码、模型标识与实际维度
docker compose --env-file docker/.env -f docker/compose.yml up -d --build
```

前端构建产物嵌入 Spring Boot static 资源，同一镜像同源提供网页和 REST。
prod profile 必须设置 DB_URL、DB_USERNAME、DB_PASSWORD、RAG_EMBEDDING_MODEL、RAG_VECTOR_DIMENSIONS；默认 secure cookie，部署在可信 HTTPS 反向代理后。Compose 已提供 DB_URL 和 DB_USERNAME，只需配置 DB_PASSWORD。
仅本地 HTTP 验证时设置 COOKIE_SECURE=false。不要将该覆盖用于公网生产环境。
镜像导出：`docker save tjlightrag:local -o docker/images/tjlightrag.tar`；镜像归档不提交到 Git。
会话保存在内存，服务重启需要重新登录。已提供知识库及成员权限、三类向量原始存储、TXT/Markdown 导入、持久化任务及真实 BPE 分块。上传后自动衔接分块、实体关系抽取、向量生成和完整索引原子切换；文档列表显示处理阶段并提供暂停/运行。已提供 naive/local/global/hybrid/mix 检索及历史来源定位，已开放多轮对话问答、流式取消和提示词预览。

## 文档导入

登录后创建/选择知识库，在“文档管理”的分页列表操作。每页可选 10/20/50/100 条；每篇文档可重建索引、查看解析后的纯文本、删除，并在状态列暂停/运行。上传文档按钮弹出多文件/目录上传对话框，目录中的相同文件名通过相对路径区分；提交文本按钮弹出粘贴文本表单。单文件支持 TXT、Markdown、PDF、DOC/DOCX、XLS/XLSX、PPT/PPTX、ODT/ODS/ODP、RTF、HTML、CSV，最多 5 MiB，统一使用 Apache Tika 4.2.0 解析。TXT/Markdown 需 UTF-8，PDF 需已有文本层（不启用 OCR）；失败文件可重试，不重复上传成功文件。

上传后后台自动解析、分块并构建知识库完整索引，成功后自动生效，无单独索引或任务菜单。默认 cl100k_base、512 token 窗口和 64 token 重叠；解析分块不需要密钥，建索引前需绑定抽取及向量模型。暂停在安全检查点停止，继续后重试未完成阶段；其他未暂停文档可独立进入新索引。删除后保留历史来源记录，停用旧索引并自动为剩余文档重建，期间检索暂不可用。

文档行的“运行”和“重建”仅请求该文档，不会自动运行其他失败或排队文档。“运行”复用已成功完成的分块检查点，“重建”强制重新抽取所选文档；其他已发布文档保留原修订，并复用兼容的完整抽取结果与分块向量。后台仍组装完整图谱和三类向量后原子切换，图谱摘要和向量合并阶段可能继续调用模型。复用严格匹配知识库、模型版本、抽取协议、tokenizer、补充抽取设置与向量维度；已发布文档不兼容时明确报错并保留旧活动代，不扩大单文档操作范围。部署需执行 V11 迁移以保存行操作范围和重建标记。

原文与任务保存到 PostgreSQL，服务重启后通过租约恢复。`RAG_INGESTION_ENABLED=false` 可暂停当前实例 worker 而保留队列。生产分块参数和版本限制、不可变修订/去重、历史修订及错误码见 docs/migration/STAGE_2.md。

## 模型配置与切换

模型调用使用管理员在“模型配置”中保存的服务地址、模型名称、API 密钥、超时和对应类型参数，按当前知识库的用途绑定执行。HTTP 和 HTTPS 地址均可直接配置，无需设置主机白名单或 HTTP 环境变量开关。基础地址例如 `http://192.168.5.68:6116/v1`，文本模型名称例如 `trs-m6`。

部署时通过安全配置注入 `RAG_MODEL_MASTER_KEY`（Base64 的 32 字节随机 AES 密钥），仅供服务端加密/解密页面保存的 API 密钥，不作为模型调用参数。主密钥默认不生成，缺失时无法保存非空 API 密钥；应与数据库备份一起保留，不能在重启时更换。不要把密钥或含密钥的 .env 提交到 Git。

“模型配置”按文本模型、向量模型、重排模型三个标签展示列表。管理员可通过“新建”弹窗配置模型，每行提供修改、删除及连接测试。编辑直接更新当前配置，不再生成或展示配置版本；密钥只返回是否已配置，编辑时留空保留原密钥。知识库所有者通过“模型用途绑定”弹窗，为当前知识库设置抽取、摘要、关键词、回答、向量及可选重排模型；不同知识库独立绑定，没有全局默认绑定。普通所有者可选择模型名称，不读取服务地址或密钥配置。

文本模型可填写“扩展参数（JSON）”，字段通过 Spring AI `extraBody` 直接加入请求正文，例如关闭支持此功能的服务端思考模式：

```json
{
  "chat_template_kwargs": {
    "enable_thinking": false
  }
}
```

扩展参数可留空或填 `{}`，仅接受最多 16 KiB 的 JSON 对象，不能包含凭据或覆盖模型名、消息、流式开关、最大输出等受控参数。参数保存到当前模型配置，连接测试及新的问答使用更新后的参数；缩短调用超时不会丢弃这些参数。索引构建时捕获独立的不可变执行快照，抽取、补充抽取、摘要及查询向量沿用对应索引的参数，避免编辑模型后混用向量空间。抽取或向量参数变更需重建完整新代后生效。参数是否支持由模型服务决定。

删除模型前需解除所有知识库的用途绑定；删除当前配置不清理历史索引及其执行快照。部署重启执行 V12 迁移：各模型保留最新配置，原全局绑定按模型身份复制到已有知识库，已有索引保留原模型参数；未被索引引用的配置历史清除。新知识库需单独配置用途绑定。

在知识库页面上传文档后，后台自动构建并激活完整的新代，直到状态显示“已就绪”才可用于问答。修改模型绑定后，在文档列表点击“重建”触发新代构建；相同维度的不同模型也需重建，不同维度按索引代隔离，支持 1..2000 维。底层历史索引 API 保留兼容，业务界面不再提供手动切换入口。

新索引优先按人（个人）、地（地点）、物（物品）、事（事件）、网（组织）提取实体，也允许有原文依据的其他类型。实体包含 `name/type/description/attributes`，按规范化后的“名称＋类型”合并；同名不同类型保持为不同节点。属性使用 `[{"name":"年龄","type":"integer","value":35}]`，保留原生 JSON 值，支持字符串、数字、布尔值及自定义属性类型。同名属性的不同类型或值均保留；省略属性视为空列表，兼容旧字符串属性对象。关系包含 `source/target/type/keywords/description`，端点使用 `{"name":"张三","type":"人"}`，按名称和类型共同解析；旧字符串端点仅在名称唯一时接受，不猜测同名实体类型。

首次及补充抽取通过 Spring AI 流式调用，启用 `response_format: {"type":"json_object"}`；普通问答不附加该约束。提示词要求先实体后关系，标准 Jackson 增量解析器也兼容 JSON 字段顺序变化及转义键。完整合法对象立即保存为未完成分块进度，只有完整 JSON、供应商成功结束、上下文与租约检查同时通过才完成分块。必需字段或记录语义无效时最多纠正一次，纠正需完整替换本轮输出；关系缺少端点时最多纠正一次，仍缺少端点则丢弃该关系。语法错误、断流、输出截断或取消不会发布部分索引。具体校验错误以安全错误码返回，不输出模型正文。

实体和关系继续保留全部来源文本块 `source_ids`，来源可定位文档及原文；该关联属于实体或关系整体，并非每条属性值的独立溯源。属性按名称归组存储为类型和值列表，读取兼容旧字符串列表。图谱展开与检索去重使用实体/关系 ID，回答上下文携带实体类型、属性类型及值、关系端点类型和关系类型，避免同名不同类型混淆；图谱与三类向量仍限定于同一知识库及索引代。

流式调用使用页面配置的超时秒数作为首段及后续增量的等待上限，持续输出允许总耗时超过该值；非流式调用仍限制总耗时。旧索引继续服务，新抽取协议版本为 `trs-typed-entity-json-v5`，需在文档列表点击“运行”或“重建”生成完整新代后切换；旧协议的未完成索引不会混入新格式检查点。部署重启会执行 V10 迁移，调整实体唯一约束为知识库、索引代、名称和类型；历史索引 ID 不改写。

## 检索证据

激活完整索引后，在知识库“检索证据”中选择 naive/local/global/hybrid/mix，查看块、实体关系、引用及原文选区。默认 mix，可调整召回数量、相似度阈值、来源策略、关键词和 token 预算；该诊断接口不产生模型回答；问答页面可选择重排。

查询固定开始时的索引代及其向量模型，支持模型切换期间读取旧代。首次默认精确 cosine，未自动启用会受过滤影响的全局 ANN；相关实验和差异见 docs/migration/STAGE_4.md。关键词未绑定时使用当前代的抽取模型，naive 不调用关键词模型。配置 `RAG_RETRIEVAL_MAX_CONCURRENCY` / `RAG_RETRIEVAL_TIMEOUT_SECONDS` 可限制实例并发及调用期限。

## 图谱查看

左侧“知识库问答”下方提供“图谱查看”。按实体类型和名称查询已发布索引中的实体，名称支持部分匹配；不填写条件可浏览当前图谱。D3 关联图按类型着色，显示实体名称与关系类型，支持拖动、缩放和重置视图。单击节点查看描述与属性，双击节点展开相邻实体，也可聚焦节点按 Enter 或空格展开。

每次查询最多显示 100 个实体及其间的 200 条关系；邻接关系每次加载 100 条，提示有更多时再次双击继续展开。图中最多显示 500 个节点、1000 条关系，按实体和关系 ID 去重。同名不同类型分别保留。图谱只读，不调用模型；当前知识库成员（含只读成员）可查看，每次展开保持原索引代并复核权限。未完成索引构建时会显示提示。

接口为 `GET /api/knowledge-bases/{kb}/graph/types`、`GET /api/knowledge-bases/{kb}/graph?type=&name=` 和 `GET /api/knowledge-bases/{kb}/graph/entities/{id}/neighbors?generationId={generationId}&offset=0`。邻接响应的 `hasMore`、`nextOffset` 用于继续读取同一节点的下一页。

## 知识库问答

绑定回答模型并激活索引后，在“知识库问答”中提问，选择五种模式、可选重排，查看流式答案和原文引用。“停止生成”中止读取并通知服务端取消；断流或模型错误显示未完成，不将部分内容视为成功。支持上下文/实际提示词预览。支持按用户和知识库隔离的持久化多轮对话，回答缓存禁用；实时和历史回复支持 Markdown 标题、列表、表格、引用和代码块，HTML 转义且危险链接过滤，外部图片只显示替代文字，未匹配引用会提示核对。

问答主界面左侧显示“对话历史”标题列表，点击可恢复并继续提问，也可“新建对话”。进入时默认新对话，输入框居中，发送后输入框移到底部；Enter 发送、Shift + Enter 换行。每轮保存原始问题、回复、完成状态及当轮索引来源；失败、取消或超时的部分内容明确标记未完成，不进入后续上下文。只读取当前用户在当前知识库的历史，其他成员和其他知识库不可读取。历史列表每页 50 个对话，消息每次加载 50 轮，可继续加载较早内容。

追问先由当前回答模型结合历史补全为独立检索问题，再按原有模式检索和可选重排；回答提示词携带用户原始问题和近期已完成的历史。最多使用最近 10 轮，在模型输入与输出预算内选取最多约 4096 token 的历史；最新一轮过长时保留带缩短标记的内容。历史仅用于理解指代和上下文，事实与引用仍以本轮索引证据为准。预览也使用对话历史，但不保存为新轮次。每个对话一次处理一个问题，过期请求不能迟到发布成功；部署重启执行 V13 迁移创建对话与轮次表。

问答请求省略 `maxTotalTokens` 时，总预算使用当前回答模型的上下文配置，预留该模型的最大输出 token 后裁剪检索内容；不会因检索默认 16000 token 而拒绝配置为 20000 token 的回答输出。显式传入的总预算仍与模型上下文共同约束请求。内部检索计划最多 64000 token，发送前再次核对实际提示词加输出预留；预算不足时问答及预览显示具体提示，流式失败保留未完成状态。

接口、SSE 事件、预算、限额、同实例取消要求及真实供应商验收边界见 [阶段 5](docs/migration/STAGE_5.md)。真实模型需在管理员页面配置，不在源码或日志存放密钥。通过本地测试不代表真实回答质量已验收。
