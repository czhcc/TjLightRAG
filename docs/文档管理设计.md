# 文档管理设计

## 1. 基线与目标

编写日期 2026-11-04，依据 `d65cef8` 的[设计基线](../DESIGN.md)和文档自动处理代码。对应[文档管理实现](文档管理实现.md)。

以文档列表承载上传、提交文本、查看、重建、删除及暂停/运行。上传后自动完成解析、分块、实体关系抽取、向量生成和完整索引发布，用户无需操作独立任务或索引菜单。

## 2. 页面及权限

| 内容 | 设计 |
| --- | --- |
| 文档表格 | 名称、大小、分块数、状态、操作 |
| 分页 | 默认每页 20 条，可选 10/20/50/100 条，支持前后翻页 |
| 全局按钮 | 上传文档、提交文本，分别打开对话框 |
| 行操作 | 重建、查看、删除；状态区域提供暂停或运行 |
| 动态状态 | 处理中显示转圈与文字，失败显示可理解的原因和重试入口 |
| OWNER、WRITER | 可上传、提交、暂停、运行、重建及删除 |
| READER | 可查看列表及解析文本，写操作禁用，后端仍独立鉴权 |

“查看”显示解析后的纯文本，不是让模型重新生成内容，也不是默认下载原始文件。“重建”重建该行文档的索引，不能悄悄变成全部文档重新运行。

## 3. 输入与上传设计

- 当前支持 UTF-8 TXT、Markdown 文件（`.txt/.md/.markdown`），单文件非空且最多 5 MiB，不支持 PDF、Word 或 OCR 解析。
- 上传对话框支持多选文件、选择目录；目录相对路径保留为来源名称，用于区分不同子目录中的同名文件。
- 文件逐一提交，展示各文件状态；部分失败后重试时跳过已成功文件，避免重复提交。
- 选择文件只加入上传队列，点击“开始上传”才调用服务端。
- 提交文本对话框包含名称、文本、格式、块大小和重叠参数。默认块大小 512 token、重叠 64 token；块大小 16～4096，重叠不得超过块大小一半。

## 4. 处理流程与状态

```mermaid
flowchart LR
    A[上传或提交文本] --> B[保存原始修订与持久化任务]
    B --> C[解析与分块]
    C --> D[自动协调索引构建]
    D --> E[抽取实体关系与生成向量]
    E --> F[验证完整索引代]
    F --> G[原子切换活动索引]
```

列表状态是解析任务、文档控制标志和索引队列的组合投影，不等同于某一张表的单一枚举。

| 典型状态 | 含义 |
| --- | --- |
| pending、processing 等解析任务状态 | 等待或正在解析、分块 |
| processed | 已完成解析与分块，不必然已发布到活动索引 |
| waiting_index | 等待索引协调 |
| indexing | 正在构建或准备发布 |
| indexed | 当前文档修订已进入活动索引 |
| paused | 用户暂停 |
| failed、cancelled | 失败或取消，按界面提示运行重试 |

暂停不删除原文或已发布索引，通过标志和租约隔离阻止过期工作继续发布；运行复用兼容检查点，重建强制重新抽取目标文档。

## 5. 索引一致性及删除

每次发布仍是完整知识库索引代：目标文档使用新处理结果，其他已发布文档复用兼容贡献。模型快照、抽取协议、分块策略、tokenizer 和向量维度必须兼容；不能兼容时明确失败，不扩大为全库重建。

通常构建失败保留旧活动代。删除文档是例外：为了让新查询不再读到被删内容，删除时先停用旧活动代，再自动构建剩余文档索引；期间可能暂时无法检索。保留必要的旧来源快照服务重建，不等于业务列表仍显示被删文档。

## 6. 实体关系抽取与依赖

抽取优先覆盖人、地、物、事、网，也接受有依据的其他类型；实体按名称加类型合并，属性包含类型与值，关系端点使用名称及类型解析。实体、关系与来源块保留关联。

流式 JSON 抽取中的完整对象可写入进度，但只有完整 JSON、语义校验及供应商成功结束全部满足才完成分块。纠正后仍引用缺失实体的关系会丢弃；取消、断流或截断不能发布部分索引。

需要配置抽取、摘要及向量用途，详见[模型配置设计](模型配置设计.md)。补充抽取、图谱合并及摘要会影响处理时长，文件字节小不代表只调用一次模型。

## 7. 验收要点

多文件/目录上传、上传后自动构建、解析文本查看、列表翻页、行级运行范围、暂停后立即继续的租约隔离、失败保留旧代、删除后的索引停用、只读权限和切换知识库清理对话框均应验证。
