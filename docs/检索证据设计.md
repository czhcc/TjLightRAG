# 检索证据设计

## 1. 基线与目标

编写日期 2026-11-04，代码基线 `d65cef8`。依据[系统设计](../DESIGN.md)、[阶段 4 方案](migration/STAGE_4.md)和现有检索实现。对应[检索证据实现](检索证据实现.md)。

在生成答案之前，独立检查知识库能够召回哪些实体、关系、文本块及来源，支持定位召回不足、阈值不合适和预算裁剪等问题。该页面不生成最终答案，也没有问答页面的可选重排步骤；自动关键词和向量查询仍可能调用模型。

## 2. 使用者与前置条件

所有知识库成员均可查询。知识库必须有 `ready` 状态的活动索引，以及可用于该代向量空间的模型快照。关键词自动提取使用本知识库绑定的关键词模型，未绑定时沿用该代抽取模型；naive 模式不调用关键词模型。

## 3. 页面、参数与模式

普通视图突出召回文本块、引用及来源回看，图谱数据和技术诊断折叠展示。参数默认值与接口一致，切换知识库时清除问题、结果和原文选区。

| 参数 | 默认值 | 设计约束 |
| --- | --- | --- |
| 查询文本 | 无 | 必填；最多 8000 字符，服务端另限制 2048 token |
| 模式 | mix | naive、local、global、hybrid、mix |
| `topK`、`chunkTopK` | 20、20 | 各 1～100 |
| `relatedChunkNumber` | 5 | 0～20 |
| `chunkSelection` | VECTOR | VECTOR 或 WEIGHT |
| 实体/关系预算 | 6000/8000 token | 分别 0～16000 |
| 总预算 | 16000 token | 1024～64000，包含规划中的提示词及预留 |
| 最小余弦相似度 | 0.2 | -1～1，和重排分数不是同一种分数 |
| 手工关键词 | 默认关闭 | 高层、低层关键词各最多 32 条，每条最多 256 字符 |

手工关键词按行输入，显式提供时跳过关键词模型。naive 始终只走问题向量与文本块分支。local 侧重实体及邻接关系，global 侧重关系及端点；hybrid 融合两者，mix 再加入直接文本块召回。

## 4. 结果与来源设计

结果包括：执行状态、模式、索引代、向量模型标识、关键词、实体、关系、文本块、引用、实际检索上下文和诊断元数据。

- 文本块显示内容、引用编号、来源位置及召回路径；共享文本块可有多个修订来源。
- 实体保留名称、类型、描述与属性；关系保留端点类型、关系类型和描述。
- 原文回看必须提供索引代、文本块、文档、文档修订和块序号，不能只凭一个文本块 ID 跨知识库读取。
- 选区使用 Unicode 码点偏移，原文按纯文本显示并高亮，避免 emoji 等字符造成定位偏差。

## 5. 算法与预算原则

一次检索只捕获一个活动索引代；实体、关系、文本块向量、图谱和来源均使用该代。查询向量必须使用该代的 embedding 快照，不能拿新绑定的向量模型解释旧索引。

召回后按确定性顺序融合、去重，补齐来源，再按完整记录裁剪上下文。实体和关系过多时，可裁剪末尾图记录为能单独放入预算的首个文本块保留空间。引用在最终块集合确定后重新编号。预算按 `cl100k_base` 估算，不作为供应商账单 token 声明。

## 6. 异常与验收

- 合法但未召回到证据时返回 `empty`；模型异常、超时、权限丢失不能伪装成空结果。
- 无活动索引、向量空间不一致、关键词格式错误、预算不足、并发超限应有可识别提示。
- 新请求或知识库切换中止旧请求，迟到结果不覆盖新视图。
- 验收覆盖五种模式分支、手工关键词跳过模型、完整块预算、来源码点选区、跨知识库/代隔离及权限撤销。

检索后需要回答时使用[知识库问答](知识库问答设计.md)；只想按名称浏览关系时使用[图谱查看](图谱查看设计.md)。
